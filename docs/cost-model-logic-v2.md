# 智慧安防成本选型逻辑 v2

V2 的重点是把内部报价拆成三条主线：功能算法研发、视频融合接入、硬件承载。

## 1. 客户需求输入

按摄像头组输入，而不是按单个摄像头输入：

- 同型号、同用途、同识别目标放在同一组。
- 每组填写路数、分辨率、厂商/型号、接入方式、接入复杂度、输出/融合要求。
- 每组再选择要识别的功能。

## 2. 功能算法研发成本

算法成本不再只写一个总价，而是拆成：

- 标准算法包/接入成本：同一功能在项目中只计一次。
- 每组规则配置成本：每个摄像头组都可能要画区域、设阈值、调规则。
- 样本验证/微调成本：现场样本差异大时追加。
- 新目标研发成本：客户要识别算法库外的新目标时追加。
- 月度算法运维：用于模型维护、规则调优、样本优化。

## 3. 视频融合接入成本

新增视频融合层，用于处理不同格式、不同摄像头型号、已有平台和多端输出：

- 标准 IP 流：RTSP/ONVIF 等常规接入。
- NVR/国标汇聚：GB28181、NVR、已有视频平台汇聚。
- 厂商 SDK/API：需要厂商接口权限和联调。
- 老旧平台/私有协议：风险较高，按保守口径估算。
- 多协议混合/待确认：客户无法确认时用于预估。

输出侧也单独计：

- 标准平台预览。
- 多端预览/大屏/移动端。
- 多格式转码/分发。
- 第三方系统/API 输出。

## 4. 硬件承载成本

硬件选型同时看两个硬约束：

- 总摄像头路数。
- 所需总算力。

所需总算力 = 算法总算力 + 视频融合总算力，再乘安全余量。  
如果单机不满足，则按高性能节点估算集群数量。

## 5. 标准成本

差异不大、默认都给客户的能力不单独展开，例如：

- 事件闭环。
- 多端提醒。
- 日报/周报/月报。
- 基础账号权限。
- 基础看板与报表。

这些统一放入“标准平台一次性成本”和“标准平台月度成本”。

## 6. AI token/API

大模型 token/API 费用不进入固定报价。  
表中只估算 AI 事件量，后续按服务包或按量计费。
